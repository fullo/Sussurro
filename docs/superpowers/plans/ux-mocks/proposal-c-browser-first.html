Proposal C — Browser-first: the meeting lives where the meeting is

The extension is the product surface for meetings: the side panel shows the live transcript next to the call, and a full-tab workspace (an extension page) hosts the editor, voice map, replay and export. The desktop app slims down to a companion: status, engines, pairing, privacy, and the existing dictation settings. Same React components in both places; data and audio never leave the app.

Notes

Why it can work: the user is already in the browser during a call; the side panel is the natural place for the live text, and a full tab gives the editor unlimited width without touching the Tauri window. Firefox gets the same pages through sidebar_action and an extension tab.

What it costs: the archive lives behind the extension, so meetings recorded from desktop Zoom/Teams later (native capture) would need a browser open to be edited — or a second host for the same components in the app. Two shells to keep in sync (side panel + full tab) instead of one.

Identity shift: Sussurro stops being "a tray app with a settings window" and becomes an engine with a browser front-end. That is a product decision, not just a layout one.
