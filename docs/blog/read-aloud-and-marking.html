Read aloud, and why every file it makes is marked

Turn any document into speech with a local model — off by default, nothing downloaded until you ask — and why every file it produces carries an inaudible watermark and signed metadata that can't be switched off.

6 min read · Feature

Since 0.11, Sussurro can read a document back to you — a transcript, a note, a companion document, or an article saved from a link — as an audio file, generated entirely on your own computer. It's an experimental, optional module: off by default, under Settings → Experimental, and it downloads nothing until you explicitly ask it to.

How it reads

Turn on Read aloud, then pick a voice per language in Models → Voices — each one lists its size and licence before you download it. The engine is Pocket TTS by Kyutai (MIT code, CC BY 4.0 voices), running through the same ONNX Runtime the app already uses for speaker labels — no Python, no GPL phonemizer, nothing sent anywhere.

An item's Audio tab gets a Generated speech section: pick the transcript or one of its documents and a language, then one button. Create when there's no speech for that document yet, or Listen once there is — it plays the saved file at once in the tab's own player. There's no separate "try it first" step and no scratch file: what you generate is what gets saved, next to the item, as speech.opus (or speech-<document>.opus). If the source text changes afterwards, the tab says the speech is out of date; Listen still plays what was made, and a second Create again button replaces it.

Article links (New → Link → Article) work the same way once you have them: the page's main text becomes a note, and with the module on its Audio tab reads it aloud like anything else.

Every file is marked — no switch to turn it off

Article 50 of the EU AI Act asks providers of text-to-speech systems to mark their output as artificially generated. Sussurro treats that as a baseline, not a checkbox: every file the module produces — a saved speech file or a voice preview in Models → Voices — is marked three ways, and none of them can be disabled.

  • An inaudible watermark. AudioSeal by Meta (MIT), our own ONNX export, embeds one fixed 16-bit code into the audio itself — the same code for every Sussurro install, identifying the software, never a person. It survives the app's own Ogg Opus encoding, MP3 and resampling, though not heavy noise, speed changes or very short clips. Its two models come bundled with your first read-aloud download, shown in the same size-and-licence confirmation; without them, nothing is spoken — marking isn't a pass added afterwards, it's part of the same pipeline that makes the audio.
  • Tags in the file. Every saved speech.opus carries Ogg comments — SYNTHETIC=1, the engine, voice and language — and the item's own frontmatter records the same facts in synthetic:. A voice preview (WAV) gets the equivalent LIST/INFO comment.
  • Signed metadata (C2PA). Each file also gets a C2PA Content Credentials manifest saying who made it (Sussurro <version>), that it's AI-generated speech, the engine/voice/language, and when — this computer's clock, no external time-stamp service. Because Ogg can't hold a manifest inline, a saved speech.opus gets a sidecar speech.c2pa next to it (the pair moves and deletes together); voice previews (WAV) carry the manifest inside the file.

Who signs it, and what that does (and doesn't) prove

Each Sussurro install makes its own self-signed certificate the first time it needs one — never at install or startup, only when the module actually generates a file. The private key lives only in the OS credential store (never on disk in the clear); the certificate names no one, just Sussurro install <8 hex digits>. A verifier will see a valid signature from an unknown, untrusted signer: no trust list vouches for a self-signed per-install certificate. What it does prove is that the file hasn't changed since it was signed, and that whoever holds that install's key made it — which is enough to link files back to the same install, but not to a real-world identity. Where no credential store is available (some Linux setups without a Secret Service keyring), files are still generated, watermarked and tagged — just left unsigned, and the app says why.

Check a file

Models → Voices has a Check a file tool, with the module on: pick any audio file (Opus, Ogg, WAV, MP3, M4A, FLAC) and it reports what the watermark detector, the tags and the signed metadata each found — running entirely on this computer, nothing uploaded, no certificate looked up online. It's built to be honest about uncertainty: a clean detection reads "made by Sussurro"; a partial or contradictory one reads "inconclusive"; a file with no trace at all reads "no Sussurro mark found" — never "human", since the absence of Sussurro's mark says nothing about a file made by something else.

Why bother with all three

A watermark can survive re-encoding but says nothing about who made the file or when. Tags are easy to strip. A signature is strong but only as trustworthy as the key behind it, and a self-signed one doesn't carry a name. Together they give a verifier three independent things to check, which is more useful than any one of them alone — and asking "is this real" is exactly the situation where you want more than one kind of evidence.

None of this needs you to do anything: it runs automatically on every file the module writes. The only thing you control is whether the module is on at all — see README → Read aloud for the full picture, including build sizes, supported voices, and what happens when you turn the module off.
