Transcribe from a link

New → Link turns a URL into a Transcription in your archive: a direct link to an audio or video file, or a page on a video platform through yt-dlp. The download is temporary; the transcript stays.

5 min read · Feature guide

A link goes through two steps, both shown in the tab: 1 · Download, then 2 · Transcribe. The audio is fetched to a temporary file in Sussurro's data folder, never in your archive. It is transcribed and cleaned like any other source, then the download is deleted. The result is a Transcription whose frontmatter records where it came from (source: url:<link>). The title is yours, or the video's title, or the file name.

Two kinds of link

  • Direct media links, such as a podcast's mp3, a .m4a, .wav, .flac, .ogg or a video file. Sussurro downloads these itself, with nothing to install.
  • Video pages on known platforms (YouTube, Vimeo, SoundCloud, Dailymotion, Twitch, TED, Bandcamp and others). These go through yt-dlp, which Sussurro does not bundle, because it changes too often to pin. Install it yourself and Sussurro finds it on your PATH or in the usual Homebrew, winget, scoop, Chocolatey, pipx or pip folders.
brew install yt-dlp        # macOS (or: pipx install yt-dlp)
winget install yt-dlp.yt-dlp   # Windows (or: scoop install yt-dlp), then restart Sussurro
pipx install yt-dlp        # Linux (or your distro's package, which can be old)

Sussurro asks yt-dlp for the audio only (an m4a stream when there is one) and runs it without a shell or a config file, one video at a time (no playlists). yt-dlp runs only for those known sites, without its generic “any page” extractor. A web page anywhere else is refused, with a hint to link the audio or video file itself. No ffmpeg is bundled, so a video whose only audio is Opus or AC-3 is refused with an explanation. Download it some other way and use the File tab.

Your responsibility

Downloading from video platforms is subject to their terms of service and to copyright. Transcribe only media you have the right to use. The tab says so too.

The rules

  • Only http and https links, with no user name or password in them (the link is saved in the item).
  • Addresses on this computer or your local network (localhost, your router, a NAS, cloud metadata addresses) are refused unless you tick Allow local network addresses for that run. Every address a host resolves to, and every redirect, is checked, and the connection goes only to the addresses that passed. yt-dlp's own connections go through the same check.
  • Links ignore the system's proxy settings, for both direct downloads and yt-dlp, so that the address check can't be bypassed. Behind a network that only allows a proxy, download the file another way and use the File tab.
  • At most 2 GB per link. Beyond that, download the file and use the File tab.
  • Cancel stops the download or the transcription and discards everything. Nothing stays in the archive, and a stuck yt-dlp is stopped with all its child processes. Temporary files left by a crash are swept at the next start.

Speakers on a link

A link is a transcription, so you can tick Identify voices to label who speaks as Voice 1, Voice 2… (rename them or link them to People afterwards). Decide before you start: the download is deleted at the end, so the voices can't be identified later from the Speakers panel, as they can for a local file.

Then what

The transcription lands in the Library like any other item: search it, add tags and participants, export .srt/.vtt subtitles, or run a recipe such as Summary on it.
