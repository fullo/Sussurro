The local API

Sussurro can expose a small HTTP endpoint on loopback so your own scripts can clean text, transcribe audio, and search history — using your live settings.

5 min read · Feature

The pipeline that powers dictation is useful outside dictation too. The local API lets any script on your machine tap into it — the same cleanup model, the same STT engine, the same history — over plain HTTP.

Turn it on

It ships off by default. Switch on Local API in Behavior → Advanced (loopback only, applies at restart), then Scripting routes in Settings → Scripting (the token-less /clean, /transcribe and /history; applies at once).

The endpoints

# clean up / translate a text with your current settings
curl -X POST --data "um so this is uh a test" http://127.0.0.1:4525/clean

# transcribe an audio file (wav/mp3/m4a/flac/ogg)
curl -X POST --data-binary @meeting.mp3 "http://127.0.0.1:4525/transcribe?ext=mp3"

# search your dictation history
curl "http://127.0.0.1:4525/history?n=10&q=sussurro"

Reading the archive (0.11)

From 0.11 a script can also read your whole archive — list, search, read and export items, their companion documents and your People — under /archive/…. It has its own switch and its own tokens: turn on Archive API in Settings → Scripting and create a token for each script, with only the scopes it needs. Read covers items, search, exports, documents and people's names; People's emails adds the emails. The token is shown once and Sussurro keeps only its SHA-256, so keep it in an environment variable:

export SUSSURRO_TOKEN=sua_...        # from Settings → Scripting
API=http://127.0.0.1:4525

# search: meetings tagged "release" since September, 20 per page
curl -G -H "Authorization: Bearer $SUSSURRO_TOKEN" "$API/archive/items" \
  --data-urlencode "q=roadmap" -d type=meeting -d tag=release -d from=2026-09-01 -d limit=20

# one item: frontmatter, text, speakers and timed lines
curl -H "Authorization: Bearer $SUSSURRO_TOKEN" "$API/archive/items/2026/09/2026-09-24-weekly-sync"

# subtitles, ready for a video editor
curl -H "Authorization: Bearer $SUSSURRO_TOKEN" -o sync.srt \
  "$API/archive/items/2026/09/2026-09-24-weekly-sync/export?format=srt"

# the formatted document a recipe wrote
curl -H "Authorization: Bearer $SUSSURRO_TOKEN" "$API/archive/items/2026/09/2026-09-24-weekly-sync/documents/document.md"

# People: names and aliases (emails only with the People's emails scope)
curl -H "Authorization: Bearer $SUSSURRO_TOKEN" "$API/archive/people"

Lists come in pages of up to 200 with an opaque next_cursor to send back; every error is JSON with a code (unauthorized, insufficient_scope, not_found, rate_limited…). The manual lists every route and filter. For now the archive API only reads; creating a note from text comes next.

What it never gives out

Speaker embeddings, voice profiles, saved audio, file paths or anything from the app's own data folder — whatever the token. Without the People's emails scope, emails are left out of items and of the markdown export, and a search can't match one either, so a script can't even test whether an address is in your archive. Browsers are refused outright, extensions included, and no CORS header is ever sent. Each token has a rate limit (a burst of 60, then 10 a second), at most two archive requests run at once so the browser extension is never starved, and revoking a token applies to the very next request.

What you can build

  • A shell alias that cleans clipboard text on demand.
  • A batch job that transcribes a folder of voice memos overnight.
  • An editor plugin that pipes selected text through your cleanup prompt.
  • A script that pulls the last n dictations into your notes.
  • A nightly job that copies this week's meeting minutes into your wiki, or a video pipeline that fetches the .srt of a transcription.
Security

Loopback-only means it isn't exposed to the network — but any process on your machine can call it. That's exactly why it ships disabled; turn it on only when you want it, on a machine you trust. Web pages can't use it: requests must name 127.0.0.1:<port> or localhost:<port> as their host, and a request carrying a web page's origin is refused. Bodies are capped (1 MiB for /clean, 200 MiB for /transcribe).

Because everything runs locally, the API is as private as the app: your text and audio go to your own model and your own disk, never to a server.
