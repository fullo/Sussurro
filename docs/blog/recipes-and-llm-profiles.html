Recipes, LLM profiles and the privacy gate

A transcript is raw material. Recipes turn it into a companion document, Ask answers questions about it, and LLM profiles decide which model does the work: Ollama, any OpenAI-compatible server, or the model Sussurro can run itself. When the server is not on your computer, Sussurro asks first, every time.

7 min read · Feature guide

LLM profiles

A profile is one LLM server plus one model. Profiles live on the Recipes screen, in the LLM profiles card. Each has a name and an API, either Ollama (native) or OpenAI-compatible (llama.cpp's llama-server, LM Studio, DS4, vLLM, Ollama's own /v1, or a hosted service that speaks /v1). It also has a server address, a model (Test connection lists the server's models), an optional context window, and an API key for OpenAI-compatible servers that need one.

One profile is the cleanup profile, picked in Settings → Cleanup. It cleans hotkey dictations, microphone sessions, files, links and the local API's /clean. Recipes and Ask let you pick a profile per run.

  • A new install starts with one profile, Local: Ollama on http://localhost:11434 with llama3.2:3b. An upgrade from 0.6 turns your old cleanup settings (server, model, API key) into this Local profile, so nothing changes until you want it to.
  • API keys are kept in the OS credential store: the macOS Keychain, Windows Credential Manager, or the Secret Service keyring on Linux (GNOME Keyring, KWallet…). The settings file only notes that the key is there. Without a working store, the key stays in the settings file and the editor says so. Keys from before 0.10 move into the store at the first start.

The bundled model: cleanup without Ollama

Installers ship a pinned llama-server from llama.cpp. With it comes a built-in profile, Local (bundled), that runs Qwen3 1.7B (Q8, Apache-2.0, about 2.2 GB) on your computer. It downloads only when you click, and the download is checked against a pinned checksum. The server starts on first use and stops after 15 idle minutes. The profile is always local, and its server can't be pointed anywhere else.

Sussurro never switches to it on its own. It's offered when no cleanup server answers: in the first-run setup (once no local Ollama, LM Studio or llama.cpp server was found), in Settings → Cleanup, on the setup banner and on the Models screen, as Use the bundled model or Use for cleanup.

Recipes

A recipe is a prompt that turns the transcript into a companion document: a markdown file saved next to transcript.md, in the Document tab. The built-in ones:

  • Formatted document (document.md): the transcript with a tl;dr, headings and tables where they help.
  • Summary, Action items, Decisions.
  • Meeting minutes and Who said what: offered only on meetings and transcriptions whose transcript names its speakers. The minutes include attendees, a timestamped agenda, the discussion, decisions and an Action | Owner | Due table, with “—” where nobody said, since the prompt tells the model never to invent.

Built-in recipes are read-only. Duplicate one, or Add recipe, to write your own. A transcript longer than the model's context window is processed in chunks and merged (map-reduce), and on meetings the chunks follow speaker turns so no statement loses its speaker. Participants are sent by name only. Their emails go along only if you tick Include participant emails for that run.

Each companion document records in its frontmatter which recipe, profile and model made it, and whether it went to an external server. Regenerate replaces a document only if you haven't edited it. If you have, the new version goes to document-2.md and your edit stays.

Ask

The Ask panel next to a document runs the recipes with one click and takes free questions: “What did we decide about the budget?”. Answers are not saved unless you click Save as document. You can also Copy or Discard them.

The privacy gate

Speech-to-text always runs on your computer. An LLM profile is external when its server is not on this machine, meaning anything other than localhost, a loopback address or a .local host. A server on your LAN counts as external unless you untick the flag yourself. Text sent to an external profile leaves your computer and is processed under that provider's terms. Sussurro never falls back from a local profile to an external one.

  • Recipes and Ask on an external profile show a confirmation every time: Send this to host?, with the document, the task, which people are named, roughly how much text (characters and tokens), the server and the model. Cancel is the default and sends nothing. The check lives in the backend, not just the dialog: a run needs a one-time permission issued for exactly that item, task, server and model, valid once and for two minutes.
  • Cleanup runs with no dialog, so an external cleanup profile needs a standing opt-in: Settings → Cleanup → Send dictations to host for cleanup, tied to that host. Point the profile elsewhere and the opt-in is void. Without it, cleanup keeps the raw text and sends nothing.
  • The Library marks every item whose text went out: ↗ Sent externally, with the hosts in the tooltip. The record is .sussurro/external-log.json in the item: date, host, profile, model and recipe of each send, never the content. Hotkey dictations don't create items, so they carry no marker.
Requires 0.10

LLM profiles, recipes, Ask, the privacy gate and the bundled model arrive together in Sussurro 0.10. The older OpenAI-compatible setup guide still applies: the server and model now go into a profile.
