Privacy policy

What the Sussurro app and the Sussurro browser extension do with your audio, your text and other data — and the few cases in which something leaves your computer.

Last updated 2026-09-28 · Covers the app and the extension, version 0.11 and later
In short

Sussurro records, transcribes and stores everything on your computer. There is no account, no telemetry, no analytics and no Sussurro server. Something leaves your computer only when you ask for it: a text you send to an LLM server that is not on your machine (after you agree to it), a link you ask to transcribe, a model you download, an update check you start, a calendar link you ask to read. The browser extension talks only to the Sussurro app on your own computer.

This page describes what the software does, as built. It is written in plain language and has not been reviewed by a lawyer. The source code is public, so every statement here can be checked against it: github.com/fullo/Sussurro.

Who publishes Sussurro

Sussurro is written and published by Francesco Fullone (DarumaHQ), who holds its copyright, as free software under the GNU AGPL v3.0 or later. This policy covers the Sussurro desktop app (Windows, macOS, Linux) and the Sussurro browser extension (Chrome, Edge, Brave and Firefox), version 0.11 and later.

The publisher does not receive, collect or store any of your data: the software has no server to send it to. Whatever you record or write stays with you, and you decide what to do with it.

What happens on your computer

Sussurro turns speech into text and keeps the result as ordinary files. All of this runs on your own computer:

  • Recording from your microphone, from your computer's sound, from audio files you open, or from a web meeting through the extension.
  • Speech-to-text with the speech models on your computer (whisper.cpp, NVIDIA Parakeet or Qwen3-ASR).
  • Cleanup, recipes and questions with a local LLM by default: Ollama on this computer, or the Local (bundled) model that Sussurro runs itself.
  • Speaker labels ("Voice 1", "Voice 2"), overlap detection, and voice recognition if you turn it on.
  • Read aloud (experimental, off by default): text-to-speech and the marks on generated audio.
  • The archive: your notes, transcriptions and meetings as markdown files in Documents/Sussurro, plus a search index.

Audio is not kept unless you ask for it (Save audio, off by default). Dictations pasted with the hotkey go into the app you are typing in, and into a local history file.

What leaves your computer, and when

Each of these happens only because of something you do. None of them sends data to the publisher.

Text sent to an external LLM server

An LLM profile whose server is not on this computer (anything other than localhost, a loopback address or a .local host, or a profile you mark as external) is external: text sent to it leaves your computer and is handled under that provider's terms. Sussurro never switches from a local profile to an external one on its own.

  • Recipes and questions on an external profile ask for confirmation every time, showing which document, roughly how much text, which server and which model. Nothing is sent until you click Send. The app enforces this itself: the run needs a single-use permission issued for that exact request, valid for two minutes.
  • Cleanup of dictations and transcriptions on an external profile needs a separate opt-in in Settings → Cleanup, tied to that server. Without it, Sussurro keeps the raw text and sends nothing.
  • Participants' email addresses are never sent to an LLM unless you tick Include participant emails for that run.
  • Every external send is logged next to the item (date, server, profile, model — never the content), and the Library marks those items as Sent externally.
  • API keys for LLM profiles are kept in your operating system's credential store (Keychain, Credential Manager, Secret Service), not in a settings file where one works.

Links you ask to transcribe

When you paste a link into New → Link, Sussurro downloads that audio or video from the site you named. For known video platforms (YouTube, Vimeo, SoundCloud and a few others) it runs yt-dlp, a separate program you install yourself, which contacts that platform. Those sites see an ordinary download request from your computer. Addresses on your computer or your local network are refused unless you allow them for that run. The downloaded file is temporary and deleted after the run.

Articles you ask to save

New → Link → Article fetches the HTML of the one page you named (at most 10 MB), under the same rules as a transcribed link: addresses on your computer or local network are refused unless you allow them for that run, every redirect is checked, and no system proxy is used. Nothing else is requested — no images, scripts, styles or other pages — and no script from the page ever runs. The site sees an ordinary request from your computer. The main text is extracted on your computer and saved as a note in your archive, with the link as its source; the page itself is not kept.

Model downloads

Speech, speaker and language models are not in the installer. Sussurro downloads each one when you ask for it (Models screen, first-run setup), or the first time you use a feature that needs it (for example speaker labels in your first meeting). If you already have Whisper models on disk, you can point Sussurro at that folder and download nothing.

Updates

When you click Check for updates, the app fetches a small file (latest.json) from the project's GitHub releases and, if you accept, downloads the new version from GitHub. Updates are signed and checked before they are installed. Sussurro does not check for updates on its own.

The Firefox extension is updated by Firefox itself, which periodically reads https://fullo.github.io/Sussurro/extension/updates.json and downloads new versions from the project's GitHub releases. That is a normal browser request with no data about you beyond what any web request carries. The Chrome build, loaded unpacked, is updated by hand.

Calendar link

If you save a private calendar link (the "secret address in iCal format" of Google Calendar, an Outlook or iCloud published calendar), Sussurro fetches it only when you ask it to add a meeting's attendees from your calendar. The link is a secret: it is kept only in your operating system's credential store, never in a settings file, an export or a log, and the app shows only its host. You can import an .ics file instead, which needs no network at all.

Things you send yourself

Sussurro doesn't send these anywhere, but you might: copied text, exported documents and subtitles, a portable configuration export (People are included only if you tick Include People; API keys and voice profiles never are), and the Copy diagnostics report (performance numbers and settings summaries, no transcripts and no keys) if you paste it into a bug report.

No telemetry, no analytics, no account

Neither the app nor the extension contains analytics, telemetry, crash reporting, advertising or tracking code, and neither asks you to create an account. There is no Sussurro server. The Firefox extension declares that it collects no data (data_collection_permissions: none).

The browser extension

The extension records web meetings on Google Meet, Microsoft Teams and Zoom in the browser and streams them to the Sussurro app on the same computer, which transcribes them.

What it captures

  • Nothing until you press Start recording in its side panel (Chrome, Edge, Brave) or sidebar (Firefox) on the meeting tab. While it records, the toolbar button shows a red REC badge on that tab. Stop, closing the tab or leaving the page ends the recording. Before that, its script on the meeting page only watches for the call's audio streams so that it can record them after Start.
  • Audio: your microphone as the page sends it, and the call's incoming audio (everyone else, mixed).
  • Names from the page: the participants' names shown on the meeting page and which of them is speaking, so remote lines can be named instead of "Voice N". It reads the page's structure only; it never clicks, opens panels or reads the chat.
  • The meeting's host name (for example meet.google.com), recorded as the item's source.

Where it goes

All of it goes only to the Sussurro app on your computer, at http://127.0.0.1, using a pairing token. The extension contacts no other server. The app accepts the connection only from a browser extension carrying that token, never from a web page. The live transcript in the side panel is kept in the extension's memory while you use it, not saved by the extension.

What it stores in your browser

  • The pairing (the app's port and the pairing token), in the extension's own IndexedDB, where the meeting pages' scripts can't read it.
  • In the extension's local storage: whether you ticked Don't show this again on the recording notice (recordingNoticeSeen), and the meeting language you last picked for each platform (meetingLanguage).

Removing the extension deletes all of it. Forget pairing in its options removes the pairing.

The local API

The app can serve an HTTP API for your own scripts and for the extension. It listens only on 127.0.0.1 (not reachable from the network), refuses requests from web pages, and is off on a new install. The extension's routes need the pairing token; archive routes need tokens you create, with scopes (participants' emails need their own scope), stored only as hashes.

Other people's data

Some of what you keep in Sussurro is about other people. You are the one who decides to collect it, and you are responsible for it under the rules that apply to you.

  • Meeting recordings capture other people's voices. Depending on where you and they are, and on your organisation's rules, you may need to tell them, and some may have to agree first. Before your first such recording the app and the extension show a notice saying so, and a "Recording other people" line stays visible while you record. The notice gives no legal advice. More in Recording meetings and consent.
  • People: the names, aliases and email addresses you enter are kept in your archive (.sussurro/people.json), so they travel with it if you sync or share the archive. They are never logged, never in diagnostics, and in a configuration export only if you ask.
  • Participants of meetings and transcriptions (names, and emails from People or a calendar you import) are written in each item's file.

Voice profiles (biometric data)

A voiceprint that identifies a person is biometric data (special-category data under GDPR art. 9). Sussurro handles it this way:

  • Off until you turn it on, person by person (Recognise this voice). It learns only from lines you linked to that person yourself, and it only suggests a name; nothing is linked without your click.
  • Your own voice ("You") is optional: you read a short paragraph aloud, and Sussurro keeps an averaged voiceprint of it, never the recording.
  • Each profile is one averaged voiceprint in the app's data folder (voices/, readable only by your user on macOS and Linux). It is never in the archive, a configuration export, diagnostics, logs or the local API, and never shown in the app.
  • Delete with Forget this voice on a person, Forget my voice, or Forget all voices in Settings → Voices. Deleting a person forgets their voice. Forgetting deletes the file outright.

Tell people before you let Sussurro learn their voice. Using it for yourself, family and friends is generally a different matter from an organisation recognising its staff or clients, where data protection law usually applies in full.

Generated speech and its marks

The read-aloud module (experimental, off by default) turns text into speech on your computer. Every audio file it generates — saved speech, Listen files and voice previews — is marked as synthetic, as the EU AI Act (art. 50) asks, and there is no switch to turn the marks off:

  • Metadata in the file (SYNTHETIC=1, the engine, the voice, the language) and in the item's frontmatter.
  • An inaudible watermark (AudioSeal) carrying one fixed Sussurro code, the same for every user. It identifies the software, never you.
  • Signed metadata (C2PA), in the version that adds it: a signature made with a key created on your computer the first time it is needed, one per installation, kept in your operating system's credential store. The signed statement says the audio was generated by Sussurro, with the engine, voice, language and time; its signer name is "Sussurro install" plus a short code derived from that key. It contains no name, account, document title or other personal data. For saved Ogg Opus speech it is a small .c2pa file next to the audio.

Check a file tells whether an audio file carries these marks. It runs on your computer and uploads nothing.

Where data is kept, and how to delete it

Everything is ordinary files under your user account, kept until you delete them. There is no retention period set by anyone else, and no copy anywhere else.

This website

This site is hosted on GitHub Pages and its pages load fonts from Google Fonts, so GitHub and Google receive the usual request data (such as your IP address) when you visit. The site itself sets no cookies and runs no analytics.

Children

Sussurro is a general-purpose tool not aimed at children, and it collects nothing from anyone.

Changes to this policy

When what the software does with data changes, this page changes with it, and the date at the top is updated. Every earlier version is in the project's public git history: history of this page.

Contact

Questions about this policy or about how Sussurro handles data: open an issue at github.com/fullo/Sussurro/issues. Issues are public, so don't include personal data or recordings.

To report a security problem privately, use GitHub's private vulnerability reporting for the repository: Report a vulnerability.
