# Sussurro 0.10.0: the speech-to-text workbench

Sussurro 0.10.0 is the first release since 0.6.3. It brings together what was
planned as 0.7, 0.8, 0.9 and 0.10. Hotkey dictation works as before. Around
it, Sussurro is now a **workbench**: voice notes, audio files, links and
meetings become markdown documents in an archive you own, and a local (or,
if you choose, remote) LLM formats and questions them.

Guides for each feature are on the [blog](../blog/index.html). The full
feature list and requirements are in the [README](../../README.md).

## What's new

### A workspace (0.7)

- A new window with a left rail: **New · Library · People · Recipes ·
  Models · Settings**. It replaces the old single-window UI.
- **A guided setup** on first launch covers permissions, the archive
  folder, a speech model, cleanup and your shortcut. *Run the setup again*
  is in Settings → About.

### Notes, files and the archive (0.7)

- **New → Microphone** records a note, or a meeting with *Meeting in the
  room*. **New → File** transcribes wav, mp3, m4a, aac, flac or ogg as a
  note or a transcription.
- A **long-form engine** cuts recordings at pauses (Silero VAD), then
  transcribes and cleans each segment while you talk. Files are decoded as
  a stream, so long recordings don't need to fit in memory.
- **Crash-safe**: the item is saved after every segment, and an interrupted
  session reopens marked *Interrupted*. A hotkey dictation during a long
  session still goes first.
- **The archive** lives in `Documents/Sussurro`: one folder per item, with
  `transcript.md` (YAML frontmatter), companion documents, subtitles and
  saved audio. The files are the source of truth, so you can edit them
  anywhere. The search index is derived and can be rebuilt.
- The **Library** has full-text search, and New sets the language and
  cleanup level for each run.
- Guide: [The archive: notes, meetings and transcriptions](../blog/archive-and-notes.html).

### Recipes, Ask, LLM profiles and links (0.8)

- **LLM profiles**: each pairs a server with a model, and speaks either
  Ollama or any OpenAI-compatible API. One profile does cleanup, and recipes
  and Ask choose one per run. **API keys are stored in the OS keychain.**
- **Recipes** write a companion document next to the transcript:
  *Formatted document*, *Summary*, *Action items*, *Decisions*, or your
  own. Long transcripts go through map-reduce.
- **Ask**: free questions about the open document. You choose whether to
  save the answer.
- **Privacy gate**: recipes and Ask on an external profile (a server off
  this machine) ask for confirmation every time. Cleanup on an external
  profile needs a standing opt-in per host. The Library marks every item
  that was sent out.
- **Links**: **New → Link** transcribes a direct media link, or a video
  page through `yt-dlp` if it's installed. The download is temporary. Local
  network addresses are refused unless you allow them for that run.
- Transcriptions have **participants**.
- Guides: [Recipes, LLM profiles and the privacy gate](../blog/recipes-and-llm-profiles.html),
  [Transcribe from a link](../blog/transcribe-links.html).

### Meetings (0.9)

- **Browser extension** for Chrome, Edge, Brave (116+) and Firefox (128+).
  It records Google Meet, Microsoft Teams and Zoom in the browser and
  streams the call to the app, which transcribes it live. The side panel
  mirrors the transcript and offers *Open in Sussurro*, *Copy as text* and
  *Create .srt*. Installing it takes one zip per browser from the release,
  and pairing takes one code from Settings → Browser extension.
- **Speakers**: your mic is always **You**. On Meet, participants' names
  come from the page. Everyone else becomes **Voice 1, Voice 2…**, told
  apart on this computer by a small speaker model (WeSpeaker, CC-BY-4.0,
  downloaded on first use). Rename voices, link them to people, or
  *Re-detect speakers*. Transcriptions get the same with *Identify voices*.
- **People**: names, emails and aliases, linked to participants
  automatically.
- **Subtitles**: `.srt` and `.vtt` for meetings and transcriptions, created
  on request (the default) or on every save.
- **Library facets**: filter by tag, category, participant and date.
- **Recording notice**: before you record other people, the app and the
  extension show a short consent reminder.
- Guide: [Record web meetings with the browser extension](../blog/meetings-extension.html).

### Advanced meetings (0.10)

- **New → System audio + mic** records a desktop call as two channels.
  The computer's sound comes through **native loopback** (WASAPI on
  Windows, a Core Audio process tap on macOS 14.2+, the PulseAudio/PipeWire
  monitor on Linux through `pulseaudio-utils`) or through any virtual
  device (BlackHole, VB-Cable, a monitor source).
- **Saved audio**, off by default: *Save audio* keeps a 16 kHz WAV per
  channel. **Delete audio** keeps the transcript.
- **Per-speaker replay**: the *Audio* tab plays the item with the
  transcript highlighted. *Play only* plays one speaker's lines back to
  back.
- **Speaker-aware recipes**: *Meeting minutes* (with an *Action | Owner |
  Due* table) and *Who said what*. Participants go to the LLM by name only,
  unless you include their emails for that run.
- **Voice map**: each line is a dot placed by how the voice sounds.
- **Multilingual cleanup**: filler words are recognised per language
  (Italian, English, Spanish, French, German), and each segment of a long
  recording is cleaned in the language that was detected for it.
- Guide: [Record desktop calls: system audio + mic](../blog/system-audio.html).

### A bundled `llama-server` (Track E)

- Installers now include a pinned, unmodified `llama-server` from
  llama.cpp (release `b11146`, SHA-256-checked at build time). It runs two
  optional extras, each as its own local process:
  - **Qwen3-ASR 1.7B**, a third speech engine (~2.5 GB, chosen on the
    Models screen). It detects the language itself. It takes no dictionary
    prompt, and Whisper large-v3-turbo stays more accurate on Italian, so
    it is never the default.
  - **Local (bundled)**, an LLM profile with **Qwen3 1.7B** (Apache-2.0,
    ~2.2 GB) for cleanup, recipes and Ask with nothing else installed. It
    is offered when no cleanup server answers and never selected for you.
    It starts on first use and stops after 15 idle minutes.

### Security and fixes

- **Local API hardening** (#215): every route accepts only a
  `127.0.0.1`/`localhost` Host of the API's port, which stops DNS
  rebinding, and refuses browser origins other than extensions. Bodies are
  capped (1 MiB `/clean`, 200 MiB `/transcribe`), and a small worker pool
  keeps a long transcription from blocking the extension. The extension
  can open or export only the meetings it recorded. `settings.json` is
  written atomically and is readable only by you on macOS and Linux.
- **Links and the bundled server** (#216): yt-dlp runs only for known video
  sites, without its generic extractor, and every connection it makes goes
  through the same local-network check as direct downloads. Links ignore
  system proxy settings. The `llama-server` helper listens on a private Unix
  socket on macOS and Linux, or on an owner-checked loopback port on Windows,
  and needs a random key that changes on every start.
- **Meeting pages can't flood the app** (#217): page events are
  rate-limited on both sides, and the silence the app inserts for gaps is
  bounded. The extension keeps its pairing out of the
  meeting page's reach, and sends the token as the first WebSocket message
  instead of in the URL.
- Import files are picked in the backend, so no path crosses from the UI.
  Archive writes are atomic, and index access is serialised.
- Parakeet no longer drops sentences after a pause in long segments (#194).

## Removed

- **Command mode** (the second hotkey that applied a spoken instruction to
  the selection). Use your OS voice control: Voice Control on macOS, Voice
  Access on Windows 11. Spoken formatting commands *inside* a dictation
  (“new line”, “a capo”, “scratch that”) stay.
- **The classic UI** and its preview switch.

## Upgrading from 0.6.x

The updater installs 0.10.0 over 0.6.x. What changes for you:

- **What's new.** An upgraded install opens on one *What's new* screen
  instead of the full setup. *Run the full setup* is there if you want it,
  and Settings → About → *Run the setup again* reopens it later.
- **Your cleanup settings become an LLM profile.** The server, model and
  API key you used for cleanup become a profile named **Local**, selected
  for cleanup. Dictation keeps working unchanged. The old keys are never
  written again. **Downgrading** to 0.6 loses a custom cleanup server (it
  falls back to Ollama on localhost), and the updater only moves forward.
- **API keys move to the OS keychain** at the first start: the macOS
  Keychain, Windows Credential Manager, or the Secret Service keyring on
  Linux (service `com.sussurro.app`). `settings.json` then records only that
  the key is in the keychain. Without a working keychain (for example a
  Linux session with no keyring daemon), the key stays in the file and the
  profile editor says so. Sussurro tries again at every start. A downgrade
  can't read keys from the keychain: enter them again.
- **Documents permission (macOS).** The archive is created in
  `~/Documents/Sussurro`. A new install asks for access during setup. On an
  upgrade, *Get started* on the What's new screen creates the folder, so
  macOS asks then and not in the middle of a recording. Allow it, or pick
  another folder in Settings → Archive.
- **Dictation history** is where it was on disk, and appears under
  Settings → Dictation history. Hotkey dictations don't become Library
  items.
- **Meetings are on by default.** There is no switch. The extension's
  routes exist whenever the local API runs, and they need the pairing
  token, so an unpaired app accepts nothing. *System audio + mic* and
  *Meeting in the room* are always in New. The first recording of other
  people shows the consent notice.
- **The scripting routes are opt-in.** `/clean`, `/transcribe` and
  `/history` now have their own switch, *Scripting routes* in
  Settings → Behavior → Advanced, which applies at once. **If your local
  API was on before, the switch starts on**, so your scripts keep working.
  On a new install it is off, and turning on the local API for the browser
  extension doesn't turn it on.
- **Command mode's shortcut** is dropped from your settings on the first
  save.
- **New downloads, only when you use them**: the pause detector (Silero
  VAD, ~0.9 MB) on the first long recording, the speaker model (~26 MB) on
  the first meeting or *Identify voices*, Qwen3-ASR (~2.5 GB) or Qwen3 1.7B
  (~2.2 GB) only if you choose them. All are checked against published
  checksums.
- **Browser extension version**: keep it equal to the app's. A mismatched
  extension tells you when the app is too old.

## Known limits in this release

- Voice N clustering was tuned on English recordings, so check the labels on
  other languages. Meet names depend on Meet's page, and they will need
  updates when it changes.
- Windows loopback capture has not been verified on real hardware yet.
  macOS system audio needs 14.2+ and the *System Audio Recording*
  permission.
- There is no echo cancellation, so use headphones for calls.
- The extension is not in the browser stores yet: Chrome, Edge and Brave
  load it unpacked; Firefox installs the Mozilla-signed `.xpi` from the
  release, which then updates itself.
- Links ignore system proxy settings. On a network that only allows a
  proxy, download the file another way and use New → File.
- Installers are still not OS-code-signed. On macOS, if Qwen3-ASR or the
  bundled model fails to start after the first right-click → *Open*, run
  `xattr -cr /Applications/sussurro.app` once.

Manual verification before the tag is tracked in #177 (notes, archive,
recipes, links) and #184 (extension, meetings, system audio).
