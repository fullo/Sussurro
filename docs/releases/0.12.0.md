# Sussurro 0.12.0: read aloud's Audio tab, tidied up

Sussurro 0.12 was originally planned to bring local read aloud — but the
maintainer folded that whole milestone into [0.11.0](0.11.0.md) instead (see
0.11's release notes and the [known voices](../blog/known-voices.html) and
read-aloud sections there). What's left under the 0.12 milestone is small: a
usability pass on the *Audio* tab that 0.11 shipped, and this release's own
docs. Update the app and the
[browser extension](../../README.md#browser-extension-meetings) together —
their versions must match.

## What's new

### One button per document in the Audio tab

- The *Generated speech* section of the **Audio** tab now shows **one
  button per document** instead of the two-button "Listen (temporary) /
  Save as speech file" pair 0.11 shipped: **Create** when there is no
  speech for that document yet, or **Listen** once there is, which plays
  the saved file at once — no generation step, no temporary file. A stale
  file (the source text changed since) still plays via *Listen*, with a
  secondary **Create again** next to it. (#327)
- **The temporary *Listen* path is gone, backend included** — not just its
  UI entry point. There is no more `listen-N.opus` scratch file written to
  the app's data folder before you decide to keep it: every generation now
  writes straight to the saved `speech.opus` (or `speech-<document>.opus`)
  next to the item, watermarked, tagged and signed the same as before.
  Anything a pre-0.12 install left behind in `tts-preview/` is swept away
  the next time the app starts, as it always was. (#327)
- **One shared in-app player** for the whole tab: the file list's per-row
  play button and the *Generated speech* section's own button now drive the
  same play/pause/seek control, instead of a native `<audio controls>`
  element in the file list. (#327)

Nothing about *what* gets generated, how it is marked (watermark + Ogg Opus
tags + C2PA-signed metadata) or the experimental module's off-by-default
gating changed — see [0.11's read-aloud
section](0.11.0.md#read-aloud-experimental-off-by-default) and
[README → Read aloud](../../README.md#read-aloud-experimental) for the full
picture, which already describes the interface this release ships.

## Also in this release

Very little else is user-visible in 0.12: at the time these notes were
written, the only merged change on top of 0.11.0 was the Audio tab pass
above (#327). Any small fixes that land on `main` before this release is
tagged (for example flaky-test-only changes) carry no user-facing behaviour
and are not repeated here.

## Known limits in this release

- The known limits carried over from 0.11 are unchanged: Teams/Zoom name
  selector sets are still unverified on real calls (#184), manual QA on real
  macOS/Windows/Linux hardware (plan
  `docs/superpowers/plans/2026-09-25-sussurro-voices.md`, section 9) is
  still open, and read aloud's watermark/signature still can't be verified
  for every file shape (no working OS credential store on some Linux
  configurations leaves files watermarked and tagged but unsigned).
- The two-voice "podcast" recipe, originally 0.12's stretch goal, is tracked
  as #259 under the 0.13 milestone instead — not part of this release.

## Upgrading

- Install the 0.12.0 app (or let the auto-updater do it) and the 0.12.0
  extension together.
- If you generated speech with 0.11's temporary *Listen* button, nothing is
  lost: only the never-saved scratch files in `tts-preview/` are gone;
  anything you chose to *Save as speech file* is untouched and still plays.
- Read aloud stays off until you turn it on in Settings → Experimental, same
  as 0.11.
