# Sussurro 0.11.0: known voices, read aloud

Sussurro 0.11 teaches the app to recognise the voices it already knows, adds
an HTTP API to your own archive, saves audio smaller, reads attendees
from a calendar file and — as an experimental module, moved in from the
0.12 milestone by a late decision — reads your documents aloud. Update
the app and the [browser extension](../../README.md#browser-extension-meetings)
together — their versions must match.

## What's new

### Known voices (suggest-only)

- **Voice profiles**: once you link a "Voice N" to a person in the speaker
  panel, Sussurro can build a private voiceprint for that person from the
  lines you confirmed — never from anything you didn't link yourself. A
  profile needs at least 60 seconds of confirmed speech from 2 documents
  before it suggests anything. (#241)
- **Suggestions**: an unlinked voice in a later meeting can show *Sounds
  like Anna · Link · Not Anna*. Nothing is ever linked without your click,
  and *Not Anna* is remembered. Settings → Voices turns suggestions off
  without deleting any profile, or deletes every profile with *Forget all
  voices*. (#242)
- **Your own voice ("You")**: an optional ~30-second read-aloud enrolment
  (Settings → Voices) so single-microphone recordings — a room meeting, a
  transcription with *Identify voices* — can label your own lines "You"
  automatically, without ever overriding a name you gave a speaker. (#243)
- Voice profiles are **biometric data** (GDPR art. 9) and are treated
  accordingly: opt-in per person, built only from your own confirmed
  links, stored only on this computer (never in the archive, an export,
  diagnostics or the API), and deletable at any time. See
  [Privacy → Voice recognition](../../README.md#voice-recognition-known-voices)
  and the blog post
  [Known voices: suggestions, not surveillance](../blog/known-voices.html).

### Overlapping speech

- **Overlap-aware "Re-detect speakers"**: when two people speak at once, the
  line keeps its main speaker and now notes who else was talking (*+ Voice 3
  also speaking*), found by a small model (pyannote segmentation-3.0, MIT,
  downloaded on first use). Overlapped stretches are left out of voice
  profiles and suggestions, so a quieter second voice doesn't skew anyone's
  profile. (#244)

### Web meeting names

- **Microsoft Teams** and **Zoom** web meetings now show participants'
  **names from the page**, the same as Google Meet since 0.9. Everyone else
  is still told apart by voice as *Voice 1, Voice 2…*. These selector sets
  are new and still need a live-call check (tracked in #184); if a page
  changes and the extension can't read the names, it falls back to
  *Voice N* rather than guessing. (#245, #246)

### Saved audio as Ogg Opus

- **Saved audio format**: a Settings → Archive setting picks Ogg Opus (the
  new default for new installs) or WAV for every run's saved channel files.
  Opus is much smaller — about a tenth the size of the 16 kHz WAV it
  replaces — with the same crash-safety (a crashed recording still leaves a
  playable file, missing at most the last second). Existing installs keep
  WAV until you change the setting; files saved before 0.11 are never
  touched. (#247)
- **Playback, decode and *Compress audio***: the WebView never has to play
  Ogg Opus itself — the app decodes it on the fly, so the *Audio* tab,
  per-speaker replay and *Identify voices* all work exactly as with WAV, on
  every OS and every WebView version. *Compress audio* (per item, or
  Settings → Archive → *Compress all*) turns older WAV recordings into Opus
  in place, losing nothing from the transcript or speaker data. (#248)

### Archive HTTP API

- Scripts can now reach your whole archive over the [local
  API](../../README.md#local-api-scripting), not just `/clean` and
  `/transcribe`: **list, search, read and export** items (including `.srt`/
  `.vtt`), read companion documents and your People, and **add a note from
  text** — the one write route in 0.11. It has its own switch (Settings →
  Scripting → *Archive API*) and its own scoped tokens (**Read**, **People's
  emails**, **Write**), shown once and stored only as a hash. Every browser
  Origin is refused, extensions included, and a token can never read
  embeddings, voice profiles, saved audio or file paths. (#249, #250, #251)
- See [README → Archive API](../../README.md#archive-api) for the routes,
  filters and a `POST /archive/items` walkthrough (including a macOS
  Shortcuts example), and the [local API blog
  post](../blog/local-api.html) for a guided tour.

### Calendar attendees

- **New → System audio + mic** and **Meeting in the room** can now read
  attendees from an `.ics` calendar file, or a private calendar link kept
  only in the OS credential store — never in settings or an export. Matching
  events overlapping the recording (or that day's events) offer to add
  their attendees as participants, and to fill in a missing email for
  someone already in the meeting; nothing is added or changed without your
  confirmation. Local and private-network calendar links are always
  refused, the same as for links. (#252)

### Read aloud (experimental, off by default)

Moved into 0.11 by the maintainer's decision on #259 (2026-09-28): "0.11
now ships read aloud (#254–#258)". It stays an **experimental, optional
module** — off by default, under *Settings → Experimental* — exactly as
the plan's P24 always required for it, so nothing changes for anyone who
doesn't turn it on.

- **Any document, read aloud.** Turn on *Read aloud* in Settings →
  Experimental, then pick a voice per language in *Models → Voices*
  (nothing downloads before you ask, and the confirmation shows size and
  licence). An item's **Audio** tab can then *Listen* to the transcript or
  a companion document — a temporary file, deleted when you close the
  document — or *Save as speech file* next to the item, read in the
  language's picked voice. The engine is [Pocket
  TTS](https://kyutai.org) by Kyutai (MIT + CC BY 4.0 voices, native
  Italian), running locally through the app's own ONNX Runtime; it writes
  files rather than speaking live. (#254 text preparation, #255 engine and
  *Models → Voices*, #256 read aloud, plus 24 kHz speech output, #309)
- **Article links.** *New → Link → Article* keeps a web page's main text —
  headings, paragraphs, lists, no menus or ads — as a note, using the same
  network rules as any link; pages behind a login, a paywall or built by
  JavaScript are refused rather than saved empty. With the module on, its
  Audio tab reads it aloud like any other item. (#258)
- **Every generated file is marked**, as the EU AI Act (art. 50) requires:
  an inaudible watermark (AudioSeal, MIT) that cannot be switched off, Ogg
  Opus comments, and **signed metadata** (a C2PA manifest, signed with a
  per-install self-signed certificate whose key lives only in the OS
  credential store) saying who made the file, that it is synthetic, and
  when. *Check a file* (Models → Voices) tells you what a file's watermark,
  tags and signature say, for anyone verifying a Sussurro recording. (#257)
- See [README → Read aloud](../../README.md#read-aloud-experimental)
  for the full picture, including what "Check a file" reports and why an
  unsigned file can still happen (no working OS credential store).

## Also in this release

- **Fixes already released as 0.10.1, 0.10.2 and 0.10.3**: `main` carries
  everything already shipped in those patch releases — Teams on
  `teams.cloud.microsoft`, Zoom's web client recording again, a per-meeting
  language menu, Firefox 140+, settings saved even when the dictation
  hotkey is taken, the extension's live connection surviving long pauses on
  Windows, and Ollama "thinking" models no longer returning empty recipes
  (see [0.10.1](0.10.1.md), [0.10.2](0.10.2.md), [0.10.3](0.10.3.md) for
  details). Nothing further to do — they're already part of this release.
- **A live level meter** next to every microphone and audio-device picker
  (New, Settings → Dictation, Your voice, and elsewhere a source is
  chosen): you see the device is picking up sound before you start
  recording, with a hint after a few seconds of silence. It only reads a
  rolling ~100 ms level — nothing is kept — and stops as soon as a real
  recording starts. (#317/#314)
- **macOS: orphaned Qwen3-ASR/bundled-model sidecars are cleaned up.** If
  Sussurro was killed rather than quit normally, a `llama-server` sidecar
  process could be left running; Sussurro now finds and stops orphans of
  its own sidecars at startup. (#325/#319)
- **An unreadable archive folder no longer empties the Library.** If the
  archive folder becomes temporarily unreadable (a permissions issue, a
  disconnected drive, a macOS privacy prompt not yet answered), the
  Library now shows an explanation instead of looking empty, and nothing
  derived from the archive — voice profiles, the search index, tracked
  source files — is touched until it's readable again. (#329/#328)
- **A privacy policy for the app and the extension**
  ([privacy.html](https://fullo.github.io/Sussurro/privacy.html)): what
  stays on your computer, what leaves it and when (model downloads, the
  updater, links and articles you fetch, external LLM profiles you set
  up), what the extension's permissions are for, and how to delete voice
  data. Security issues can now be reported privately on GitHub.
  (#324/#267)

## Known limits in this release

- Voice-suggestion and overlap-detection thresholds were tuned on English
  recordings (voice profiles were re-checked on Italian in the V0 spike and
  hold at the same threshold; the underlying *Voice N* clustering thresholds
  are not part of this release). Check labels on other languages.
- The Teams and Zoom name selector sets are new and unverified on real
  calls; issue #184 tracks that manual check.
- Manual QA on real macOS, Windows and Linux hardware (plan
  `docs/superpowers/plans/2026-09-25-sussurro-voices.md`, section 9) is
  still open — see #253's acceptance criteria.
- **Read aloud's watermark and signature can't be verified for every file
  shape.** Without a working OS credential store (for example a Linux box
  with no Secret Service keyring), generated files are still watermarked
  and tagged but left unsigned. The watermark survives the app's own Opus,
  MP3 and resampling, but not heavy noise, speed changes or very short
  excerpts. The two-voice podcast recipe (originally 0.12's stretch goal)
  did not move with the rest of read aloud — it's tracked as #259 under the
  0.13 milestone instead.
- Article extraction (*New → Link → Article*) refuses pages behind a login
  or a paywall, and pages whose text is built by JavaScript, rather than
  saving them empty.

## Upgrading

- Install the 0.11.0 app (or let the auto-updater do it) and the 0.11.0
  extension together.
- New installs default to Ogg Opus for saved audio; an existing install
  keeps WAV until you change *Saved audio format* in Settings → Archive.
- Voice recognition, own-voice enrolment, the archive API, calendar
  attendees and read aloud are all **off until you turn them on** —
  nothing changes for you until you do.
